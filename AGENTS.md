# AGENTS.md

For humans and coding agents changing this repo. The front door for users is
[README.md](README.md); this file is the maintainer contract: architecture
boundaries, exact commands, local CI, conventions and known traps.

## Overview

This repo renders **Mili's *Ga1ahad and Scientific Witchery*** as a 200 column x
56 row, 24-bit truecolor terminal music video, then encodes it to a 1920x1080
H.264/AAC MP4 carrying the full-length original audio with no cuts, trims or
offset (only re-encoded to AAC).

It is not a video editor and not a game: the only animation model is *"every frame is a pure function of the
timestamp `t`"*, which makes frames exactly reproducible and lets rendering run
in parallel and be re-rendered by segment (there is no automatic resume).

Story text and every proper noun live in the `content/` TOML tree (lint-enforced);
scene code keeps layout, glyphs and telemetry labels. Lyric lines are read from
the VTT through `self.cues` / `cue_progress` / `cue_text`; copying VTT lyric
text into code is rejected by `audit-text`.

Dependency direction (a reverse import is a bug): `config.py` is a leaf;
`glyphs` depends only on config; `canvas` on config + glyphs; `motion` on
config/canvas + numpy only (it lazily imports `art` inside Dialog to reuse the
official conversation-window contract, never at module level); `art` on
canvas/timeline; `assets` on canvas/glyphs and lazily on `portraits` for the real
busts; `portraits` on assets/canvas (the assets -> portraits import is deferred
inside functions, so there is no import cycle); `timeline`, `audio` and
`content` are independent data layers (each only imports the `config` leaf).

`frame` composes all of them and loads the scene registry, then hands the canvas
to `raster` (cells -> pixels); `crt` is an optional pixel-level output stage that
consumes that 2000x1120 raster and emits 1920x1080 frames (it depends only on
`config` plus numpy/Pillow and is imported lazily).

`crt_gpu` depends on `crt` and optional ModernGL, with one EGL context per worker;
`encode` consumes the
renderer (and therefore `crt` when enabled) and `live` consumes canvas/renderer;
`raster` itself consumes canvas/glyphs only. `cli` and `verify` are the only
top-level orchestrators.

Scene modules may import core drawing modules and `scenes/base.py`, never `cli`,
`encode`, `verify` or `live`.

Entry points: `./ga1ahad_tui` -> `ga1ahad/cli.py:main`; `python -m ga1ahad`;
`_segment` is an internal subprocess worker, not a user command.

Where a change of type X starts: timing or lyrics -> `timeline.py` (+
`SCENE_SPECS`); a new scene -> `timeline.SCENE_SPECS`, `scenes/__init__.py`,
`scenes/<key>.py`, `content/en/scenes/<key>.toml`, `content/en/ui.toml`;
animation/widgets -> `art.py`; a shared cinematic primitive (camera/typography/
transition/physics) -> `motion.py`; glyphs/fonts -> `glyphs.py`; post-processing ->
`raster.py` (in-frame FX) or `crt.py` (output CRT stage); encoding/muxing ->
`encode.py`; text/names -> `content/` only; verification -> `verify.py` /
`audit.py`; CLI flags -> `cli.py`.

## Commands

Run from the repo root. `./ga1ahad_tui` is the canonical entry point; it uses
the provisioned `.venv` (or `uv run` if no venv) and fixes NixOS shared libs.

| Task | Command |
|---|---|
| environment + timeline | `./ga1ahad_tui info` |
| live playback (200x56 terminal) | `./ga1ahad_tui live` (add `--mute` in non-audio shells) |
| full MP4 render (CRT on by default) | `./ga1ahad_tui render --workers 16` (about 9 min; the CRT resample is memory-bandwidth bound) |
| full MP4 with required GPU CRT | `./ga1ahad_tui render --backend gpu --workers 8` |
| install optional GPU packages | `UV_CACHE_DIR=.uv-cache uv sync --locked --extra gpu` |
| backend/encoder policy tests | `./tools/py -m unittest discover -s tests -v` |
| real GPU parity and timing | `./tools/py tools/check_gpu.py` |
| flat MP4 render (no CRT) | `./ga1ahad_tui render --no-crt --workers 16` |
| render any segment | `./ga1ahad_tui render --start S --end E --workers 8 --out clip.mp4` |
| acceptance clip with required GPU CRT (Scene 5 storm) | `./ga1ahad_tui render --backend gpu --start 184.5 --end 198.3 --workers 8 --out ga1ahad_scene5_kiss.mp4` |
| still frame | `./ga1ahad_tui png --at 17.6` -> `build/frame.png` |
| still with the MP4 CRT stage | `./ga1ahad_tui png --at 17.6 --crt` |
| contact sheet | `./ga1ahad_tui sheet` -> `build/contact_sheet.png` |
| cue sync review frames | `./ga1ahad_tui dump --out build/cues` |
| content validation | `./ga1ahad_tui content` |
| content lint | `./ga1ahad_tui audit-text` |
| all checks | `./ga1ahad_tui check` (74 checks; `--quick` skips the sampled-frame sweep = 73) |
| scratch Python | `./tools/py script.py` (same venv + libs) |
| rebuild venv (uv only; resolution dry-run verified) | `UV_CACHE_DIR=.uv-cache uv sync --locked` |

Toolchain: Python >= 3.13 (`pyproject.toml`), numpy >= 2.5, Pillow >= 13,
ffmpeg with libx264 + AAC. `encode.find_ffmpeg()` finds ffmpeg on PATH or in
the Nix store; `GA1AHAD_FFMPEG=/path/to/ffmpeg` overrides it. `GA1AHAD_FONT`
overrides the DejaVu Sans Mono path for non-bold text (bold derives from the
font family). `--locale xx` (or `GA1AHAD_CONTENT_LOCALE=xx`)
selects `content/xx/` as a deep overlay on `content/en/`.

Render defaults to `--backend auto`: probe an actual GPU frame before launching
workers; report the device or CPU fallback reason. `--backend gpu` fails if
hardware is unavailable. `png`/`sheet` default to CPU and accept the same backend
flag. Without `--workers`, GPU uses up to 4 workers, CPU up to 8.

Optional `--encoder h264_vaapi` uses `--qp` rather than `--crf`/`--preset`, and probes a
real encode before workers start. See `docs/GPU_RENDERING.md` for requirements,
NixOS driver environment, benchmark scope and the remaining CPU stages.

## CI flow

There is **no hosted CI** in this repository (`.github/`, `.gitlab-ci.yml`,
`Jenkinsfile` etc. are absent). The merge gate is the local verifier; run all
stages below before committing, in this order. The numbers are gate order, not
the verifier's internal section numbers.

| # | Stage | Command (exact) | Fails on |
|---|---|---|---|
| 1 | content lint | `./ga1ahad_tui audit-text` | a hard-coded proper noun, retired stand-in or VTT lyric copy in the scanned sources/content/docs |
| 2 | content validate | `./ga1ahad_tui content` | missing screenplay/title for a scene, unknown `{term}`, unreadable locale |
| 3 | renderer + lyric sync | `./ga1ahad_tui check --quick` (73 checks; lyric sampling 3 -> 1 per cue, frame sweep skipped) | scene import error, canvas size drift, a cue's rendered subtitle != VTT text |
| 4 | MP4 structure + A/V sync | `./ga1ahad_tui check` (stage 3 included) | wrong codec/resolution/fps/duration/frame count, audio truncated or shifted (envelope correlation <= 0.97), or no CRT signature |
| 5 | frame sanity sweep | separate section of the same `./ga1ahad_tui check` | black/empty sampled frames |
| 6 | acceptance clip | separate section of the same `./ga1ahad_tui check` | wrong format/frame count, clip audio not the correct source segment, or no CRT signature |
| 7 | CRT output stage | separate section of the same `./ga1ahad_tui check` | wrong filter frame size/type, non-deterministic frames, or a missing scanline/bezel signature |

Stages 3 and 4 render frames in-process (stage 4 decodes the MP4 too). Missing
deliverables do **not** fail `check`: `check_video`/clip checks emit WARN and
drop their checks, so a missing MP4 or clip silently lowers the count (e.g.
`check --quick --video missing.mp4` still exits 0 with far fewer checks).
Re-render the deliverables first if you need the full gate.

For compositor/encoder changes also run the policy tests and real-GPU parity
commands above before rebuilding. They are separate from the 74-check verifier;
the GPU check must fail, rather than skip, when hardware cannot be exercised.

## Conventions

- **主代理向人汇报时，用明快、易懂的语言。** 先说做了什么、结果如何，再补充理解结果所需的背景。
  设想读者没有跟过实现过程，也不熟悉相关领域。少用缩写和专有名词，必须用到时，先用一句白话说明。
- **修改视频画面时，大胆尝试。** 在构图、镜头节奏和转场上探索不寻常的做法，给画面更多表现力。
  别因为担心验收过不了就提前放弃有意思的想法，让实际画面来检验创意。
- **Every depiction of Claude's avatar MUST use 2D anime artwork and retain
  her virtual appearance.** Follow `claude.webp` as the character reference.
  In a live-action fusion, her part of the image must remain recognizably 2D
  anime. See [Claude's avatar](docs/SCENE_AUTHORING.md#claudes-avatar).
- Chrome rows 0, 1, 53, 54, 55 are owned by `frame.Chrome`; scene drawing is
  clipped to rows 2..52 (`C.CONTENT_Y0/Y1`) by the Renderer, and any direct
  row-list write that bypasses the clip is discarded and fails `verify`.
- ALWAYS derive visuals from `t` only. No wall clock, no unseeded `random`
  (use `random.Random(seed)` seeded from frame/scene constants). The CRT stage
  (`crt.py`) follows the same rule: grain seed, rolling-band phase and flicker
  all derive from `t`.
- NEVER hard-code a proper noun, dialogue line or banner in scene Python. Use
  `ctx.terms` / `ctx.script` (or `self.T` / `self.script`) and put text in
  `content/en/...`; then run `audit-text`.
- Lyrics MUST be read from the VTT via `self.cues` / `cue_progress(ctx, i)` /
  `cue_local(ctx, i)` / `cue_text(i)` (local cue index inside the scene). Never
  copy lyric text into code; `audit-text` rejects VTT lyric copies.
- A new scene MUST be registered in `timeline.SCENE_SPECS`, `scenes/__init__.py`
  MODULES, and have a `content/<locale>/scenes/<key>.toml` screenplay; its class
  `NAME` must equal the spec key.
- ALWAYS draw human <-> LLM conversation content with `art.llm_dialog`: ONE
  portrait 9:16 window per scene (`|8*w - 9*h| <= 1`; the standard window is
  55x49 cells = 550x980 px at `C.DLG_SLOTS[0]`, with margin-left 1, margin-top
  1 and margin-bottom 1 inside the content band). Secondary panes / inquiry
  and error notices / trace and verdict readouts are sections *inside* that
  window -- never a second dialog window.
- The right stage (`x >= C.STAGE_X`, 136 columns) is reserved for scene
  animation; `check` fails the frame sweep if a marked dialog cell lands there.
  Only a short, commented `Scene.DIALOG_EXEMPT` span may break the rule (special
  transitions). See `docs/SCENE_AUTHORING.md` for the dialog contract.
- ALWAYS treat `ga1ahad.vtt` and `ga1ahad_audio.wav` as immutable inputs.
- The MP4 render applies the CRT output stage by default (`crt.py`, strength
  `C.CRT_STRENGTH` = 1.0). `--no-crt`, `--crt-strength 0` and `GA1AHAD_CRT=0`
  must keep the flat path (2000x1120 raw frames + ffmpeg `-vf scale`); with CRT
  on the worker feeds 1920x1080 raw frames and ffmpeg only encodes.
- GPU acceleration must preserve the CPU reference's geometry, bloom, seeded
  grain and quantisation. Never report Mesa software rendering as GPU use.
  Explicit GPU requests never silently fall back. Cross-backend comparisons
  allow at most 1 channel level difference and mean error below 0.001; repeated
  timestamps within a backend must be byte-identical. No GPU dependency may
  be imported by the CPU path. VAAPI is an independent, explicit encoder choice.
- CRT curvature is capped: the visible screen edge and the four corners must
  stay within 1% of the frame width/height (currently 0.7%/0.8%). `check`
  measures that corner inset from a flat-grey probe; raise `CURVATURE` /
  `BEZEL_RADIUS` only together with that contract.
- ALWAYS re-render the deliverables after visual changes:
  `./ga1ahad_tui render --backend gpu --workers 8`, then
  `./ga1ahad_tui render --backend gpu --start 184.5 --end 198.3 --workers 8 --out ga1ahad_scene5_kiss.mp4`,
  then regenerate `docs/preview.png` from the new video and run `./ga1ahad_tui check`.
  Both deliverables require the GPU CRT stage; an unavailable GPU is an error.
- Commit each completed change after the applicable checks. Use
  `type(scope): imperative summary` (e.g. `fix(scene5): ...`) and explain in
  the body what was verified.

## Security model

Fully offline: no network calls, no secrets, no user data. ffmpeg is invoked
locally on files in the repo; the only trust boundary is the input assets
(VTT/WAV/webp) and the `content/` TOML, which are repo-controlled. Never add
telemetry, network fetches or credentials.

## Pitfalls

- **`ffmpeg` is not on PATH on NixOS.** `encode.find_ffmpeg()` globs the Nix
  store; if it fails, set `GA1AHAD_FFMPEG`.
- **NixOS PyPI wheels need extra libs.** numpy/Pillow may fail to import
  without `libz.so.1` and `libstdc++.so.6` in `LD_LIBRARY_PATH`; `./ga1ahad_tui`
  and `./tools/py` bootstrap it automatically. Plain `python` may not.
- **POSIX semaphores are blocked in this sandbox.** Parallel rendering therefore
  launches `_segment` subprocesses; do not replace it with
  `multiprocessing`/`concurrent.futures.ProcessPoolExecutor`.
- **MPEG-TS concat makes `avg_frame_rate` inexact.** The verifier therefore
  reads `r_frame_rate` for the 30 fps assertion; do not "fix" that check by
  comparing `avg_frame_rate` strings.
- **Scene import errors are swallowed at render time.** A missing scene module
  is silently skipped; other import/init errors print a traceback; the renderer
  substitutes a diagnostic panel, so a broken scene can render a fallback instead
  of hard-failing. Read stderr and `./ga1ahad_tui check` output when a scene
  looks generic.
- **The package directory is `ga1ahad/`, the repo directory is `ga1ahd/`.** Run
  `python -m ga1ahad`, not `python ga1ahad`.
- **Each render owns its segment directory.** `render_video` now writes into a
  private `build/segments/<output>-<random>/` directory and removes it on
  success, so a full render and a segment preview can run concurrently without
  corrupting each other's `.ts` files. Do not hard-code `build/segments/seg_*.ts`.
- **`build/` is gitignored.** Render segments, audio analysis, stills and
  contact sheets live there; never commit them.
- **Committed binaries are large** (`ga1ahad.mp4` ~310 MB with the CRT
  stage, `ga1ahad_scene5_kiss.mp4` ~34 MB). Re-render them instead of editing;
  keep both in sync with the code and with `docs/preview.png`.
- **uv's default cache is not writable here.** Use
  `UV_CACHE_DIR=.uv-cache uv sync --locked` if you must rebuild the venv.
- **Content is strict only for term-shaped placeholders.** An unknown
  `{lower_snake_case}` term aborts before rendering; unmatched or literal single
  braces pass through, and `{{`/`}}` produce literal braces. The lint also
  scans `content/` for retired stand-in names (`content/en/audit.toml` is the
  only allowed place to name them).
- **CPU rendering cost (historical):** full song ~9 min with 16 workers and the CRT stage on; a
  heavy glitch frame can cost ~100 ms of raster time. The CRT stage adds roughly
  0.1 s of CPU per frame single-threaded (curvature resample is the hot spot) and
  its grain/scanlines raise the H.264 bitrate ~60 % at CRF 18. With 16 workers
  the resample is memory-bandwidth bound, so more workers do not scale linearly;
  use `--no-crt` or segment renders (`--start/--end`) while iterating.
- **`art.llm_dialog` refuses invalid rects.** A conversation window that is not
  portrait 9:16 (`|8*w - 9*h| <= 1`), violates the left/top/bottom margins or
  leaves the left lane raises `ValueError` at render time; do not fall back to
  `art.dialog` for a conversation window (that silently bypasses the dialog
  sweep).
